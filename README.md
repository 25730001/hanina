### coreseek_v0.5 (2026-11-16) 프로토타입 전환
와이어프레임(v0.4)을 바탕으로 프로토타입 단계에 들어가며, 사용자 계정을 도입하고 첫 화면의 정보 구조를 단순하게 다시 짰습니다. 0.4와 비교한 변경 사항입니다.

**추가**
- **계정 기능**: 오른쪽 위 로그인 버튼에서 로그인과 회원가입. 로그인 상태는 새로고침해도 유지
- **입력 검증**: 아이디는 영문 소문자, 숫자, 밑줄 4~20자. 비밀번호는 영문과 숫자를 섞어 8자 이상. 회원가입 시 비밀번호 확인
- **오류 안내 6종**: 짧은 아이디, 약한 비밀번호, 비밀번호 확인 불일치, 이미 있는 아이디, 틀린 비밀번호, 서버 연결 실패
- **비밀번호 보호**: 비밀번호 원문은 저장하지 않고, 무작위 값(salt)을 섞은 SHA-256 해시만 저장
- **계정 저장소 두 가지**: 기본은 브라우저 저장(localStorage). `js/app.js`의 `SHEET_URL`을 설정하면 구글 시트(Apps Script)에 저장
- `server/Code.gs`, `server/README.md`: 구글 시트 연동용 서버 코드와 설정 순서

- `pages/prototype_v0.5/index.html`: 프로토타입 v0.5 보관본 (CSS, JS, 데이터를 파일 하나에 포함)

## 2.1 제품 개요

**코어시크**는 헬스장에 처음 가는 사람이 운동 이름을 몰라도, **운동할 부위나 눈앞의 기구만 골라서** 맞는 운동과 하는 방법, 조심할 점을 바로 찾을 수 있게 돕는 모바일 웹서비스입니다.

현재 버전(v0.5)은 공개 운동 데이터 300건, 외부 데이터 연동, 초보자 기준의 탐색 기능에 더해 **사용자 계정**을 갖춘 프로토타입입니다. 다음 단계에서는 **생성형 AI(Claude)**를 서비스의 중심에 두어, 초보자가 자기 말로 묻고 자기에게 맞는 답을 받는 경험으로 확장합니다.

> **한 줄 피치**
> 헬스장에 처음 가면 기구 이름도 쓰는 법도 몰라 러닝머신만 타다 돌아옵니다. 코어시크는 부위와 기구만 고르면 초보자 말투의 운동 방법을 보여 주고, Claude가 "무릎이 안 아픈 하체 운동"처럼 자연스러운 질문에도 답하게 만들어 혼자서도 겁먹지 않고 첫 운동을 시작하게 합니다.

## 2.2 배경

### 왜 이 문제를 골랐나
헬스장 등록은 쉽지만 **처음 한 달을 버티는 것**은 어렵습니다. 초보자가 가장 먼저 부딪히는 벽은 체력이 아니라 **정보의 벽**입니다.

| 초보자가 겪는 상황 | 원인 |
|---|---|
| 기구 앞에서 서성이다 지나친다 | 기구 이름도, 의자 높이를 맞추는 법도 모름 |
| 검색해도 원하는 답이 안 나온다 | 대부분의 운동 정보는 "랫풀다운"처럼 **운동 이름을 알아야** 찾을 수 있음 |
| 영상을 봐도 내 상황과 다르다 | 자료 대부분이 숙련자 기준이고, 영어 자료가 많음 |
| 해도 되는지 모르겠다 | 내 수준에 맞는지, 혼자 해도 안전한지 판단할 기준이 없음 |

### 기존 방법의 한계
| 방법 | 한계 |
|---|---|
| 개인 트레이닝(PT) | 비용 부담이 커서 초보자 대부분이 선택하지 않음 |
| 영상 플랫폼 검색 | 운동 이름을 알아야 하고, 정보가 흩어져 있음 |
| 운동 기록 앱 | 이미 운동을 아는 사람의 기록 도구라 "무엇을 어떻게"를 알려 주지 않음 |

코어시크는 이 빈자리, 즉 **"이름을 몰라도 찾을 수 있고, 초보자 눈높이로 설명하는"** 안내에 집중합니다.

## 2.3 목표

### 제품 목표
1. **이름 없이 찾기**: 부위, 기구, 자연어 질문만으로 원하는 운동에 도착한다.
2. **초보자 우선**: 쉬운 운동, 혼자 해도 안전한 운동이 먼저 보인다.
3. **바로 따라 하기**: 기구 맞추는 법, 순서, 조심할 점을 한 화면에서 우리말로 본다.
4. **막히지 않기**: 조건을 너무 좁혀 결과가 없어도 다음 행동을 안내한다.
5. **이어서 쓰기**: 계정으로 내 운동 기록을 이어 갈 수 있다. (v0.5 계정 도입, 기록 연결은 v0.7)

### 성공 지표 (프로토타입 사용성 테스트 목표치)
| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 과제 성공률 | 80% 이상 | "등 운동 하나를 찾아 기구 맞추는 법까지 보기"를 안내 없이 완료한 비율 |
| 도착까지 걸린 시간 | 60초 이내 | 같은 과제의 평균 완료 시간 |
| 도착까지 누른 횟수 | 3번 이하 | 홈에서 운동 방법 화면까지 |
| 0건 화면 이탈 | 0명 | 결과가 0개일 때 제안 버튼이나 초기화로 이어진 비율 |
| 회원가입 완료율 (v0.5) | 90% 이상 | 가입을 시작한 사람 중 오류 안내만 보고 스스로 가입을 마친 비율 |
| AI 답변 정확도 (v0.6 이후) | 90% 이상 | 테스트 질문 30개 중 데이터에 있는 운동만으로 올바르게 답한 비율 |

## 2.4 타깃 사용자

### 주 사용자
**헬스장 등록 1~3개월 차 초보자**
- 운동 이름은 거의 모르지만 "오늘은 하체"처럼 부위는 정할 수 있다
- 트레이너 없이 혼자 운동한다
- 헬스장 안에서 휴대폰으로 바로 찾아본다

### 페르소나 (이해를 돕기 위해 만든 가상 인물)
> **지수, 24세, 대학생**
> 헬스장에 등록한 지 2주. 친구가 등 운동으로 랫풀다운을 하라고 했지만, 기구 앞에서 의자 높이를 어떻게 맞추는지 몰라 그냥 지나쳤다. 비어 있는 기구 앞에서 바로 휴대폰으로 방법을 보고 싶고, 무엇보다 "이렇게 해도 되나?"를 물어볼 곳이 필요하다.

### 주요 사용 상황
| 상황 | 사용자가 하는 일 | 코어시크가 주는 것 |
|---|---|---|
| 운동 전 계획 | "오늘은 가슴" | 홈 첫 블록에서 부위 버튼 한 번으로 초급 운동부터 |
| 기구 앞 | 머신을 보고 사용법을 찾음 | 기구로 걸러 보기, 기구 맞추기 안내 |
| 기구가 사용 중 | 같은 부위의 다른 운동 찾기 | 조건 유지한 채 기구만 바꿔 보기 |
| 다음에 또 볼 때 | 저장한 운동을 다시 찾음 | 보관함, 계정 로그인 |
| 질문이 생김 | "무릎이 아픈데 해도 돼?" | (v0.6) Claude의 안전 안내와 대체 운동 |

## 2.7 생성형 AI 기능 상세 (Claude)

### 왜 생성형 AI인가
검색과 필터는 **사용자가 조건을 알고 있을 때** 잘 동작합니다. 하지만 초보자의 진짜 질문은 "무릎이 안 아픈 하체 운동", "20분밖에 없는데 뭐 하지"처럼 **조건이 아니라 문장**입니다. Claude는 이 문장을 이해해 코어시크의 데이터 안에서 답을 찾아 주는 **번역기이자 코치** 역할을 합니다.

### 기능별 설계
| ID | 사용자가 하는 일 | Claude가 하는 일 | 결과 |
|---|---|---|---|
| AI-01 자연어로 찾기 | "무릎이 덜 부담되는 하체 운동 알려줘" | 질문을 부위, 난이도, 기구, 조건으로 바꾸고, 300개 데이터 안에서 고른 운동과 이유를 답함 | 운동 카드 목록과 한 줄 이유 |
| AI-02 첫 루틴 | 목표, 주 횟수, 시간, 쓸 수 있는 기구 선택 | 초보자 기준(주 2~3회, 8~12회 반복)에 맞춰 데이터 안의 운동으로 주간 루틴을 구성 | 요일별 루틴, 각 운동 상세로 연결. 로그인한 사용자는 루틴 저장 |
| AI-03 설명 작성 | (운영자) 버튼 한 번 | 운동 순서와 근육 정보를 바탕으로 설명, 기구 맞추기, 조심할 점 초안 작성 | 사람이 검수한 뒤 데이터에 반영 |
| AI-04 질문하기 | 상세 화면에서 "허리가 아픈데 해도 돼요?" | 해당 운동 정보 안에서 답하고, 통증은 멈추고 전문가와 상의하도록 안내 | 짧은 답변과 대체 운동 |
| AI-05 후기 요약 | 후기가 쌓인 운동을 엶 | 후기에서 효과를 느낀 부위와 자주 나온 팁을 요약 | 세 줄 요약 |

### 동작 구조
```
사용자 브라우저
  │ 질문 (로그인한 경우 아이디 포함)
  ▼
중계 서버 (서버리스 함수 또는 Apps Script)   ← API 키 보관, 요청 횟수 제한
  │ 시스템 지침 + 질문 + 관련 운동 데이터
  ▼
Claude API
  │ 정해진 형식(JSON)의 답: 운동 번호 목록, 이유, 안내 문구
  ▼
화면: 기존 운동 카드와 상세 화면으로 보여 줌
```
- 현재 서비스는 GitHub Pages 정적 사이트라 **API 키를 화면 코드에 넣을 수 없습니다.** 키를 숨기는 중계 서버를 둡니다. v0.5에서 만든 구글 Apps Script 서버(`server/Code.gs`)를 같은 방식으로 확장할 수 있습니다.
- Claude는 **코어시크 데이터에 있는 운동 번호로만** 답하게 해서, 없는 운동을 지어내지 않게 합니다.
- AI 응답이 실패하거나 늦으면 **기존 검색과 필터로 자연스럽게 넘어갑니다.**
- 로그인하지 않은 사용자도 AI 기능을 쓸 수 있되, 요청 횟수를 더 적게 제한합니다.

### 답변 원칙 (시스템 지침에 넣을 내용)
1. 코어시크 데이터 안의 운동만 추천한다.
2. 초보자 말투로, 짧고 구체적으로 답한다.
3. 통증, 부상, 질환에 관한 질문에는 진단하지 않고, 운동을 멈추고 전문가와 상의하도록 안내한다.
4. 식단, 보충제, 약에 대한 조언은 하지 않는다.
5. 모르는 것은 모른다고 하고, 일반 검색으로 안내한다.

### 품질 관리
- 테스트 질문 30개(부위, 기구, 상황, 통증 관련 질문 포함)를 만들어 버전마다 같은 질문으로 확인합니다.
- AI-03으로 만든 설명은 **반드시 사람이 검수**한 뒤 반영하고, 데이터의 `meta`에 AI 작성 여부를 기록합니다.

### 개발 과정의 Claude 활용 (v0.5까지)
- 9주차 탐색 기능 코드 작성과 테스트
- v0.5 회원가입, 로그인 코드와 구글 시트 연동 서버 코드 작성, 자동 테스트
- 운동 데이터 문장 다듬기 (번역투, 괄호 정리)
- 공개 운동 데이터와 API 조사
- PRD와 변경 이력 등 문서 작성

모든 결과물은 팀이 확인한 뒤 반영했습니다.

## 2.9 탐색 규칙

### 검색
- 범위: 운동 이름, 영문 이름, 부위, 기구, 쓰는 근육
- 비교 전에 띄어쓰기를 지우고 소문자로 바꿉니다. "스쿼트", " 스 쿼 트 ", "SQUAT"의 결과가 같습니다.

### 필터
같은 묶음 안에서는 하나만 맞아도 나오고(OR), 묶음끼리와 조건끼리는 모두 맞아야 나옵니다(AND).

| 묶음 | 값 | 기준 필드 |
|---|---|---|
| 부위 | 가슴, 등, 하체, 어깨, 팔, 복근 | category |
| 난이도 | 초급, 중급 | difficulty |
| 기구 | 맨몸, 머신, 덤벨, 바벨 | equipment |

| 조건 | 기준 필드 | 통과 조건 |
|---|---|---|
| 설명이 있는 운동 | description | 값이 있음 |
| 미는 운동 / 당기는 운동 | force (외부 데이터) | 밀기 / 당기기 |
| 여러 근육 같이 / 한 부위만 집중 | mechanic (외부 데이터) | 복합 / 고립 |

### 정렬
| 정렬 | 기준 |
|---|---|
| 초보자 추천순 (기본) | 초급, 머신이나 맨몸, 설명이 있는 운동이 먼저. 같으면 많이 찾는 순, 이름순 |
| 많이 찾는 순 | popularity 큰 순 |
| 별점 높은 순 | 후기 평균 별점 높은 순, 후기가 없으면 뒤로 |
| 쉬운 운동부터 | 초급, 중급 순 |
| 이름 가나다순 | 운동 이름 |

정렬은 결과 목록에만 적용하고 원본 데이터 순서는 바꾸지 않습니다.

### 결과 없음과 초기화
- 결과가 0개면 마지막에 고른 조건부터 하나씩 빼 보며, 결과가 생기는 조건을 "OO 조건을 빼면 N개가 나와요"와 버튼으로 제안합니다.
- 초기화는 검색어, 부위, 난이도, 기구, 조건, 정렬을 모두 기본값으로 돌립니다.
- 데이터를 불러오지 못한 경우는 결과 없음과 다른 화면과 문구로 안내합니다.

| AI가 없는 운동이나 틀린 자세를 안내 | 부상 위험, 신뢰 하락 | 데이터 안의 운동 번호로만 답하게 하고, 테스트 질문 30개로 버전마다 확인 |
| 통증, 부상 관련 질문 | 의료 조언으로 오해 | 진단하지 않고 운동을 멈추고 전문가와 상의하도록 안내 |
| API 사용 비용 | 사용자가 늘면 비용 증가 | 요청 횟수 제한, 같은 질문 결과 저장 |
| 계정 보안 (v0.5) | 프로토타입 수준이라 로그인 시도 제한, 비밀번호 찾기가 없음 | 비밀번호는 해시로만 저장, 다른 곳에서 쓰는 비밀번호를 쓰지 않도록 안내. 정식 공개 전 인증 방식 보강 |
| 브라우저 저장 계정의 한계 | 다른 기기에서 같은 계정으로 로그인 불가 | 구글 시트 연동(`SHEET_URL`)으로 전환 |
| 더미 데이터 (순위, 후기, 일부 설명) | 실제 정보로 오해 | 데이터의 `meta`에 예시임을 기록. 서버 저장 후 실제 데이터로 교체 |
| 운동 순서 번역 검수 부족 | 어색하거나 틀린 표현 | 체육 전공자나 트레이너에게 검수 요청 |
| 외부 데이터 주소 의존 | 근육 정보와 일부 조건 사용 불가 | 실패해도 저장 데이터로 동작 (구현 완료) |
