## 1. 한 줄 소개

헬스장에 처음 가는 사람이 운동 이름을 몰라도, 운동할 부위나 기구만 고르면 하는 방법과 조심할 점을 바로 찾을 수 있는 운동 안내 웹서비스입니다.

## 2. 배경과 문제

헬스장에 처음 가면 기구는 많은데 이름도 모르고 쓰는 법도 모릅니다. 검색을 하려 해도 "랫풀다운", "시티드 로우" 같은 운동 이름을 알아야 찾을 수 있어서, 결국 익숙한 러닝머신만 타다 돌아오는 경우가 많습니다.

우리가 풀려는 문제는 세 가지입니다.

1. **이름을 몰라서 못 찾는다.** 대부분의 운동 정보는 운동 이름으로 검색해야 나옵니다.
2. **나에게 맞는지 모른다.** 초보자가 해도 되는지, 지금 비어 있는 기구로 할 수 있는지 판단하기 어렵습니다.
3. **어떻게 하는지 모른다.** 영어 자료가 많고, 기구를 어떻게 맞추는지와 무엇을 조심해야 하는지가 빠져 있는 경우가 많습니다.

## 3. 목표

| 목표 | 확인 방법 |
|---|---|
| 운동 이름을 몰라도 원하는 운동에 도착한다 | 홈에서 부위 하나를 누르고 운동 카드 하나를 누르면, 두 번 만에 운동 방법 화면이 열린다 |
| 초보자에게 맞는 운동이 먼저 보인다 | 탐색 화면의 기본 정렬이 초보자 추천순이고, 홈 추천 운동은 모두 초급이다 |
| 조건을 너무 좁혀도 막히지 않는다 | 결과가 0개일 때 어떤 조건을 빼면 몇 개가 나오는지 알려 주는 버튼이 항상 나온다 |
| 하는 방법을 우리말로 읽을 수 있다 | 운동 300개 모두 우리말 운동 순서가 있다 |

## 4. 타깃 사용자

**주 사용자: 헬스장 등록 1~3개월 차 초보자**

- 운동 이름은 거의 모르지만 "오늘은 가슴", "오늘은 하체"처럼 부위는 정할 수 있다
- 트레이너 없이 혼자 운동한다
- 휴대폰으로 헬스장 안에서 바로 찾아본다

**가상 사용자 예시** (이해를 돕기 위해 만든 인물입니다)

> 지수, 24세, 대학생. 헬스장에 등록한 지 2주가 됐다. 친구가 등 운동으로 랫풀다운을 하라고 했는데 기구 앞에서 의자 높이를 어떻게 맞추는지 몰라 그냥 지나쳤다. 머신이 비어 있을 때 바로 휴대폰으로 방법을 보고 싶다.

## 5. 사용 흐름

```
홈
 ├─ 부위 고르기 (가슴, 등, 하체, 어깨, 팔, 복근)  ─┐
 ├─ 검색창에 입력하고 Enter                         ├─→ 탐색
 ├─ 많이 찾는 운동 순위에서 고르기  ─────────────────┼─→ 운동 상세
 └─ 처음이라면 이 운동부터에서 고르기  ──────────────┘
탐색
 ├─ 난이도, 기구, 조건으로 좁히기
 ├─ 정렬 바꾸기
 └─ 운동 카드 누르기  ─→ 운동 상세
운동 상세
 ├─ 쓰는 근육, 기구 맞추기, 운동 순서, 조심할 점 보기
 ├─ 저장하기  ─→ 보관함
 ├─ 후기 남기기
 └─ 기구가 사용 중이면 목록으로 돌아가 다른 기구 고르기
```

## 6. 기능 요구사항

우선순위는 Must(꼭 필요), Should(있으면 좋음), Could(나중에)로 나눴습니다.

| ID | 기능 | 우선순위 | 상태 |
|---|---|---|---|
| F-01 | 저장된 운동 데이터 300개 불러오기 | Must | 완료 |
| F-02 | 외부 공개 데이터에서 쓰는 근육과 동작 유형 불러오기 | Should | 완료 |
| F-03 | 검색 (운동 이름, 영문 이름, 부위, 기구, 근육) | Must | 완료 |
| F-04 | 필터 (부위, 난이도, 기구, 조건) | Must | 완료 |
| F-05 | 정렬 5가지 | Must | 완료 |
| F-06 | 결과 개수와 적용한 조건 개수 표시 | Must | 완료 |
| F-07 | 결과 없음 안내와 조건 빼기 제안 | Must | 완료 |
| F-08 | 전체 조건 초기화 | Must | 완료 |
| F-09 | 운동 카드 태그를 눌러 바로 걸러 보기 | Should | 완료 |
| F-10 | 30개씩 더 보기 | Should | 완료 |
| F-11 | 운동 상세 (설명, 쓰는 근육, 기구 맞추기, 운동 순서, 조심할 점) | Must | 완료 (설명, 기구 맞추기, 조심할 점은 1~16번만) |
| F-12 | 관심 운동 저장과 최근 본 운동 | Must | 완료 |
| F-13 | 운동 후기 (별점, 효과를 느낀 부위, 한 줄 후기) | Should | 완료 (이 기기에만 저장) |
| F-14 | 홈 많이 찾는 운동 순위 | Should | 완료 (예시 수치) |
| F-15 | 전체 메뉴 (사용법, 내 기록 지우기, 데이터 출처) | Should | 완료 |
| F-16 | 여러 사람의 후기를 함께 모아 보기 | Could | 계획 (서버 필요) |
| F-17 | 후기를 바탕으로 효과 부위를 요약해 주는 AI 기능 | Could | 계획 |
| F-18 | 17~300번 운동의 설명, 기구 맞추기, 조심할 점 채우기 | Should | 계획 |

## 7. 화면 구성

| 화면 | 들어가는 것 |
|---|---|
| 홈 | 서비스 소개와 검색창, 부위 바로가기, 많이 찾는 운동 상위 5개 차트, 처음 하는 사람을 위한 추천 운동 6개 |
| 탐색 | 검색 보드(부위는 늘 보이고 난이도, 기구, 조건은 펼쳐서 고름, 그 아래 검색창), 결과 개수, 정렬, 초기화, 운동 카드 목록 |
| 운동 상세 | 대표 사진, 이름과 태그, 별점 요약, 설명, 쓰는 근육, 기구 맞추기, 운동 순서, 조심할 점, 운동 후기, 저장 버튼, 출처 안내 |
| 보관함 | 관심 운동, 최근 본 운동 (탭으로 전환) |
| 전체 메뉴 | 사용법 3단계, 내 기록 개수와 지우기, 데이터 출처 |

하단 탭은 홈, 탐색, 보관함 세 개입니다. 전체 메뉴에는 다른 화면과 겹치는 이동 버튼을 넣지 않았습니다.

## 8. 탐색 규칙

### 검색
- 찾는 범위: 운동 이름, 영문 이름, 부위, 기구, 쓰는 근육
- 띄어쓰기와 대소문자를 무시합니다. "스쿼트", " 스 쿼 트 ", "SQUAT"의 결과가 같습니다
- 검색어가 비어 있으면 전체를 보여 줍니다

### 필터
같은 묶음 안에서는 하나만 맞아도 나오고(OR), 묶음끼리와 조건끼리는 모두 맞아야 나옵니다(AND).

| 묶음 | 고를 수 있는 값 | 기준 필드 |
|---|---|---|
| 부위 | 가슴, 등, 하체, 어깨, 팔, 복근 | category |
| 난이도 | 초급, 중급 | difficulty |
| 기구 | 맨몸, 머신, 덤벨, 바벨 | equipment |

| 조건 버튼 | 기준 | 통과 조건 |
|---|---|---|
| 설명이 있는 운동 | description | 값이 있음 |
| 미는 운동 | force (외부 데이터) | 밀기 |
| 당기는 운동 | force (외부 데이터) | 당기기 |
| 여러 근육 같이 | mechanic (외부 데이터) | 복합 |
| 한 부위만 집중 | mechanic (외부 데이터) | 고립 |

외부 데이터를 불러오지 못하면 아래 네 조건 버튼은 꺼지고, 다시 불러오기 버튼이 나옵니다.

### 정렬
| 정렬 | 기준 |
|---|---|
| 초보자 추천순 (기본) | 초급, 머신이나 맨몸, 설명이 있는 운동일수록 앞. 같으면 많이 찾는 순, 그다음 이름순 |
| 많이 찾는 순 | popularity가 큰 순 |
| 별점 높은 순 | 후기 평균 별점이 높은 순. 후기가 없으면 뒤로 |
| 쉬운 운동부터 | 초급 다음 중급 |
| 이름 가나다순 | 운동 이름 |

정렬은 결과 목록에만 적용하고 원본 데이터 순서는 바꾸지 않습니다.

### 결과 없음과 초기화
- 결과가 0개면 마지막에 고른 조건부터 하나씩 빼 보고, 결과가 생기는 조건을 "OO 조건을 빼면 N개가 나와요"와 버튼으로 알려 줍니다
- 초기화를 누르면 검색어, 부위, 난이도, 기구, 조건, 정렬이 모두 기본값으로 돌아가고 300개가 다시 보입니다
- 데이터를 불러오지 못했을 때는 결과 없음과 다른 화면과 문구로 안내합니다

|---|---|---|
| 이름, 영문 이름, 부위, 난이도, 기구, 운동 순서, 사진 | Free Exercise DB (퍼블릭 도메인) | 실제 |

| 1~16번 설명, 기구 맞추기, 조심할 점 | 수업 실습용으로 AI가 쓴 글 | 더미 |
| popularity (많이 찾는 수치) | 수업 실습용 예시 값 | 더미 |
| sampleReviews (1~16번 예시 후기 2개씩) | 수업 실습용 예시 글 | 더미 |
| 사용자가 남긴 저장, 최근 본 운동, 후기 | 사용자의 브라우저 | 이 기기에만 저장 |

각 운동의 `meta` 필드에 실제(real), 더미(dummy), 비어 있음(unknown)을 기록해 두었고, 화면에서도 실제와 더미 표시를 붙여 보여 줍니다. 필드별 설명은 `data/README.md`에 있습니다.

### 저장 위치
| 저장 키 | 내용 |

| recentExerciseIds | 최근 본 운동 번호 목록 (최대 10개) |

## 14. 버전 관리 규칙

### 번호 붙이는 법
- 이 문서의 버전이 곧 프로젝트 버전입니다. 지금은 **0.4**입니다.
- 화면, 기능, 데이터 중 하나라도 바뀌어서 GitHub에 올릴 때는 **0.1씩 올립니다.** 다음 변경은 **0.5**가 됩니다.
- 오타 수정처럼 아주 작은 변경은 버전을 올리지 않고, 다음 버전의 변경 이력에 함께 적습니다.
- 정식 공개 버전은 1.0으로 정합니다.

### 바꿀 때마다 하는 일
1. 맨 위 표의 **현재 버전**, **이전 버전**, **마지막 수정일**을 고칩니다.
2. 아래 **15. 변경 이력** 맨 위에 새 버전 칸을 만들고, 이전 버전과 비교해 무엇이 바뀌었는지 적습니다.
3. 본문(기능 요구사항, 화면 구성, 탐색 규칙 등)에서 바뀐 부분도 함께 고칩니다.
4. `index.html`의 `style.css?v=…`, `app.js?v=…` 번호를 바꿔서 새 화면이 바로 보이게 합니다.
5. GitHub에 올릴 때 커밋 메시지 앞에 버전을 적습니다. 예) `v0.5 상세 화면에 운동 영상 추가`
6. 와이어프레임, 프로토타입처럼 한 단계가 끝나면 그 시점의 `index.html`, `css`, `js`, `data`를 `pages/` 아래에 `단계이름_v버전` 폴더로 복사해 보관합니다. 폴더 이름은 영어로 씁니다. 예) `pages/wireframe_v0.4`, `pages/prototype_v0.6`

### 변경 이력 쓰는 법
버전마다 날짜와 한 줄 요약을 쓰고, 바뀐 내용을 아래 네 가지로 나눠 적습니다. **무엇이, 어디서, 어떻게** 바뀌었는지가 보이게 이전 상태와 새 상태를 함께 씁니다.

| 구분 | 뜻 |
|---|---|
| 추가 | 없던 화면, 기능, 데이터가 새로 생김 |
| 변경 | 있던 것이 다르게 바뀜 (이전 → 이후) |
| 삭제 | 있던 것을 뺌 |
| 수정 | 잘못 동작하던 것을 고침 |

다음 버전은 아래 틀을 복사해서 15번 맨 위에 붙여 쓰면 됩니다.

```
### 0.5 (YYYY-MM-DD) 한 줄 요약
**추가**
-
**변경**
- (이전) → (이후)
**삭제**
-
**수정**
-
```
